## Request and baseline

On 2026-09-30, pull latest `main`, make the command/binary `edge` consistently
with `edgejs-quickjs`, create review builds, and ask for review before publishing
a patch to wasmer.wtf and wasmer.io.

The checkout was fast-forwarded to `f3170cc3`. The pre-existing local change to
`quickjs-wasm/wasmer.toml` (`0.1.4` to `0.2.0`) was preserved. Other local files
and submodule work must not be included in the change.

Production metadata reports `wasmer/edgejs` and `wasmer/edgejs-quickjs` at
`0.2.4`; candidates will use `0.2.5`. Staging metadata initially timed out.
Root source metadata still names the experimental `syrusakbary/edgejs`; review
package metadata must explicitly use `wasmer/edgejs` without rewriting the
pre-existing QuickJS version change.

## Action plan

1. Rename the standard package atom/module to `edge`, including all command
   references and WASI atom annotations. Put the canonical `edge` command first;
   retain the existing `edgejs` alias for callers of older packages.
2. Package both WASIX builds as `bin/edge` through the shared `dist-only` target
   and point their distribution manifests at that file. Internal `.wasm` build
   filenames remain compatible with runtime test/build scripts.
3. Build versioned review distributions/WEBCs, validate manifests and archives,
   and smoke-test explicit `edge`, default entrypoint, and existing aliases.
4. Record artifact provenance, hashes, verification, and any build/runtime
   blockers here. Request user review before either registry publication.
